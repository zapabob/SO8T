# 2026-02-08 パイプライン自動再開（Auto-Resume）の修正ログ

## 問題点

電源投入時や再起動時に、既存のチェックポイントがあるにもかかわらず「[START] Starting new pipeline run」と表示され、最初から実行されてしまう。

## 原因分析

1. **ファイル名プレフィックスの不整合**:
   - 保存時 (`_save_checkpoint`): `pipeline_checkpoint_x.json` (固定)
   - 読み込み側 (`_load_latest_checkpoint`) 及び初期化時: `moonshot_checkpoint_x.json` (動的)
   - この不整合により、読み込み側がファイルを見つけられず、初期状態からスタートしていた。
2. **状態復元の欠如**:
   - `execute_full_pipeline` においてチェックポイントをロードしても、`self._current_phase` や `self._current_data` に反映されていなかったため、定期バックグラウンド保存が正しく機能しない可能性があった。

## 修正内容

1. **`integrated_moonshot_pipeline_2025_2026.py` の修正**:
   - `_save_checkpoint` メソッドを修正し、パイプライン名に基づいたプレフィックス（デフォルト `moonshot_`）で保存するように変更。
   - `execute_full_pipeline` 回収ロジックを強化し、ロードされた値を `self._current_phase` 等の内部メンバに即座に反映するように修正。
2. **既存ファイルのマイグレーション**:
   - 既存の `pipeline_checkpoint_*.json` を `moonshot_checkpoint_*.json` にリネームし、次回の起動から即座に復旧可能にしました。

## 検証

- 起動時に `[RECOVERY] Phase '...' completed. Resuming from '...'.` というログが表示され、前回の続きから開始されることを確認。
